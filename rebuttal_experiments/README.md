# Rebuttal experiments

Code and data to reproduce the additional experiments of the revised ArtSeek paper: five VQA benchmarks, the ablations, other backbones (Gemma 3, Mistral Small 3.1), the memorisation and oracle-retrieval probes, latency, and the human evaluation.

Set up the repository first as described in the main [README](../README.md): environment, `.env`, downloaded resources and a Qdrant server with the WikiFragments collection. Every command below is run from the repository root.

```
rebuttal_experiments/
  common/            shared code: runner, phi-4 judge, oracle probe, analysis scripts
  artpedia_vqa/      ArtPedia-VQA (ours) + memorisation probe
  aqua/              AQUA subset
  artquest/          ArtQuest subset
  licn_heldout/      LICNHeldOut (ours, Wikidata)
  artcurate_aic/     ArtCurate-AIC (ours, Art Institute of Chicago)
  cross_benchmark/   index manifest, coverage, cross-benchmark tables
  human_eval/        human evaluation (items, references, answers, ratings)
  slurm/             SLURM templates
```

Each benchmark folder has a `data/` folder with its questions and a `results/` folder where runs are written. Only `results/tables/` (the summary tables we obtained) is versioned; model outputs are regenerated by the scripts.

## Systems

Every run uses vLLM with greedy decoding, a 16,384-token context and at most 4 concurrent sequences. The generator is `Qwen/Qwen2.5-VL-32B-Instruct-AWQ` unless stated.

| variant | what changes |
|---|---|
| `base` | the backbone alone (no card, no retrieval) |
| `full_classify` | ArtSeek: artwork card + retrieval, policy taught by the one-shot example |
| `full_noclassify` | no artwork card |
| `full_systemprompt` | policy described in the system prompt instead of the one-shot example |
| `full_alwaysretrieve` | at least one retrieval is forced |
| `full_singleretrieve` | exactly one retrieval, then answer |
| `full_classify_noartist` / `_notags` / `_reliable` | artist / tag / both fields removed from the card |
| `full_classify_gated` | artist shown only when LICN's confidence is at least 0.6 |
| `base_gemma3`, `base_mistral3` | `google/gemma-3-27b-it` (bf16, 2 GPUs) / `RedHatAI/Mistral-Small-3.1-24B-Instruct-2503-quantized.w4a16` alone |
| `full_seeded`, `full_gemma3`, `full_mistral3` | ArtSeek with *seeded* retrieval on Qwen / Gemma 3 / Mistral |

Seeded retrieval runs before the model's first turn and allows no further tool calls: queries are the card's artist (if its confidence is at least 0.8) and the question, with 20 fragments each, merged by score, and the top 10 kept. Gemma and Mistral cannot emit Qwen's tool calls, so they need it; `full_seeded` is the matching Qwen run.

Answers are judged by `microsoft/phi-4` (0/1/2 correctness and 0-1 recall against the reference). We used the long-answer rubric for ArtPedia-VQA and the short-answer rubric (`--rubric aqua`) for the other four benchmarks. Confidence intervals are 95% percentile bootstraps over paintings (10,000 resamples, seed 20260828).

## Running a benchmark

The same three steps for every benchmark (`<b>` is the folder name). They can be run directly or with the templates in `slurm/`:

```bash
# 0. a Qdrant server reachable by the jobs (see slurm/qdrant_server.sh)
QDRANT_BIN=... QDRANT_STORAGE=... sbatch rebuttal_experiments/slurm/qdrant_server.sh

# 1. answers, one job per variant (resumable)
sbatch rebuttal_experiments/slurm/run.sh <b> base
sbatch rebuttal_experiments/slurm/run.sh <b> full_classify
# ... full_noclassify, full_systemprompt, base_gemma3 (add --gres=gpu:2), ...

# 2. judge (only what is not judged yet)
sbatch rebuttal_experiments/slurm/judge.sh <b> base full_classify full_noclassify full_systemprompt

# 3. tables (CPU), written to <b>/results/tables/
export ARTSEEK_EXP_DIR=rebuttal_experiments/<b>
for s in main_tables paired_stats latency nonanswer failure_taxonomy clustering_sensitivity; do
    python rebuttal_experiments/common/analysis/$s.py
done
```

Without SLURM, the same steps are:

```bash
export ARTSEEK_EXP_DIR=$PWD/rebuttal_experiments/<b> ARTSEEK_IMAGES_DIR=$PWD/data/external/<images>
python rebuttal_experiments/common/run_experiment.py --variant full_classify \
    --vqa-path rebuttal_experiments/<b>/data/<file>.json --out-dir rebuttal_experiments/<b>/results
python rebuttal_experiments/common/analysis/build_runs_jsonl.py
python rebuttal_experiments/common/judge.py --pass answer --rubric aqua --variant full_classify
```

If a run is interrupted by a lost Qdrant connection, the failed items are recorded as errors and skipped on resume. Remove them first with `python rebuttal_experiments/common/retry_failed.py --results-dir rebuttal_experiments/<b>/results --apply`.

## Benchmarks

### ArtPedia-VQA (`artpedia_vqa/`)

For each of the 339 ArtPedia test paintings, Qwen3-8B (text only) writes one visual and one contextual question-answer pair from the painting's human-written sentences: 678 questions. 13 images are no longer downloadable, leaving 652 questions on 326 paintings. The questions are in `data/artpedia_vqa.json`.

```bash
python rebuttal_experiments/artpedia_vqa/download_images.py      # needs data/external/artpedia/artpedia.json
python rebuttal_experiments/artpedia_vqa/build_vqa_dataset.py    # GPU; only to rebuild the questions
```

Extra analyses:

- **Memorisation probe.** The bare backbone is asked to name each painting and its artist. A painting is *obscure* when both are wrong.
  ```bash
  sbatch rebuttal_experiments/slurm/python.sh artpedia_vqa rebuttal_experiments/artpedia_vqa/obscure_probe.py
  sbatch rebuttal_experiments/slurm/python.sh artpedia_vqa rebuttal_experiments/artpedia_vqa/ground_truth.py extract-artists
  sbatch rebuttal_experiments/slurm/python.sh artpedia_vqa rebuttal_experiments/artpedia_vqa/ground_truth.py judge-probe
  python rebuttal_experiments/common/analysis/obscure_report.py
  python rebuttal_experiments/common/analysis/main_tables.py --subset obscure   # also paired_stats, evidence, routing
  ```
- **Evidence judge.** Were the needed facts in the retrieved fragments?
  ```bash
  python rebuttal_experiments/common/analysis/build_fragment_cache.py       # CPU
  sbatch rebuttal_experiments/slurm/python.sh artpedia_vqa rebuttal_experiments/common/judge.py --pass evidence --variant full_classify --variant full_systemprompt
  python rebuttal_experiments/common/analysis/evidence.py
  python rebuttal_experiments/common/analysis/query_quality.py
  ```
- **Oracle retrieval.** The same index is queried with question + reference answer.
  ```bash
  sbatch rebuttal_experiments/slurm/python.sh artpedia_vqa rebuttal_experiments/common/oracle_probe.py
  python rebuttal_experiments/common/analysis/build_runs_jsonl.py && python rebuttal_experiments/common/analysis/build_fragment_cache.py
  sbatch rebuttal_experiments/slurm/python.sh artpedia_vqa rebuttal_experiments/common/judge.py --pass evidence --variant oracle
  python rebuttal_experiments/common/analysis/oracle_analysis.py
  ```
- Retrieval policy (`routing.py`), forced retrieval (`alwaysretrieve.py`) and the artist field of the card (`artist_conditioning.py`).

The same evidence and oracle steps were run on AQUA.

### AQUA (`aqua/`)

[AQUA](https://github.com/noagarcia/ArtVQA) (Garcia et al., ECCV Workshops 2020). 326 of the 663 test paintings that have both a visual and an external-knowledge question are sampled (seed 20260828), with one question of each type: 652 questions. The subset is rebuilt deterministically from the AQUA files and SemArt (not redistributed here):

```bash
python rebuttal_experiments/aqua/build_aqua_subset.py --aqua-dir <ArtVQA/AQUA>   # images -> data/external/semart/images
```

### ArtQuest (`artquest/`)

[ArtQuest](https://zenodo.org/records/10453925) (Bleidt, Eslami & de Melo, WACV 2024, CC BY 4.0). 200 test paintings with all six question types (technique, type, school, timeframe, artist, title), 1,200 questions, in `data/artquest_vqa.json`.

```bash
# unzip the ArtQuest archive into data/external/artquest/
python rebuttal_experiments/artquest/build_artquest_subset.py --n-paintings 200   # also extracts the images from SemArt
python rebuttal_experiments/artquest/artquest_score.py   # exact match / contains / judged, per type, vs. published baselines
```

### LICNHeldOut (`licn_heldout/`)

Paintings by LICN's 2,501 artist classes (the ArtGraph artists), none of them among the 116,475 ArtGraph training artworks. Each question targets one LICN head: artist (P170), movement (P135 -> `style`), genre (P136) and material (P186 -> `media`). The reference answers are Wikidata statements. There are 762 questions, in `data/licn_vqa.json`.

```bash
python rebuttal_experiments/licn_heldout/download_images.py
python rebuttal_experiments/licn_heldout/licn_analysis.py     # accuracy of each head, effect of the card per head
# to rebuild the benchmark: artgraph-rdf.zip from https://zenodo.org/records/6337958
python rebuttal_experiments/licn_heldout/build_artgraph_index.py --facts <artgraph-rdf>/artgraph-facts.ttl
python rebuttal_experiments/licn_heldout/build_licn_benchmark.py
```

### ArtCurate-AIC (`artcurate_aic/`)

251 public-domain paintings of the Art Institute of Chicago (CC0) with a curatorial description. Qwen3-8B writes up to six conceptual questions per painting (iconography, narrative, person, technique, context, and multihop, which needs both the description and a second text) from the curatorial texts, which are stored with every question. There are 1,492 questions, in `data/artcurate_vqa.json`, and the source texts are in `data/artcurate_corpus.json`.

```bash
python rebuttal_experiments/artcurate_aic/fetch_artworks.py --n 260    # corpus + images
python rebuttal_experiments/artcurate_aic/build_questions.py          # GPU; only to rebuild the questions
```

## Cross-benchmark analyses (`cross_benchmark/`)

```bash
python rebuttal_experiments/cross_benchmark/build_index_manifest.py --num-proc 16   # every page in the index (CPU)
python rebuttal_experiments/cross_benchmark/coverage_and_routing.py   # help/hurt, routable headroom, index coverage
python rebuttal_experiments/cross_benchmark/summary.py                # all benchmarks side by side
python rebuttal_experiments/cross_benchmark/decomposition.py          # retrieval calls per question
```

Index coverage is the share of a benchmark's paintings whose title matches a page of the retrieval index.

## Human evaluation (`human_eval/`)

**Task.** Every system describes each painting in four short numbered parts: SUBJECT, FIGURES, PLACEMENT (tradition, school, period) and EVIDENCE (up to three works, artists or sources). The prompt is `PROMPT` in `run_local_models.py`.

**Systems.** `base` (Qwen2.5-VL-32B), ArtSeek (`artseek_multiquery`: the full pipeline with three seeded queries, i.e. the card's artist if its confidence is at least 0.8, a short subject guess by the model, and a generic query) and GPT-5.5 (`gpt-5.5-2026-04-23`, no tools). Answers go through the same rule-based formatting pass (`normalize_answers.py`) before being shown.

**Paintings (15).** The list is in `data/items.json`.

- *Wikipedia tier (10).* The painting's English Wikipedia article contributed at least 8 fragments to the retrieval index, and at most 6 Wikipedia language editions have an article about it. Paintings whose artist is among LICN's classes are preferred. Items were drawn from a seeded shuffle with at most two paintings per century and one per artist (`build_candidate_pool.py`, `enrich_pool.py`, `select_items.py`).
- *Gallery tier (5).* Paintings of the Galleria Nazionale della Puglia "Girolamo e Rosaria Devanna" (Bitonto). None of them has a Wikipedia article, and their painters are outside LICN's label space. Eligible works are paintings on display with an ICCD catalogue record (scheda) and a photograph, and whose catalogued subject maps, through a fixed lexicon, to an English Wikipedia page with at least 8 fragments in the index. Five were drawn with a seeded shuffle, one per subject category, artist and subject page (`select_gallery.py`, which needs the gallery catalogue). One of them, `devanna-010`, was shown with a photograph of a different work than the one it was annotated with, so it is excluded from the analysis. The ICCD records of the selected works are in `data/gallery/`, and the photographs used (longest side 1024 px) are in `images/`. They are included only to reproduce this study; for any other use, contact the gallery.

**References.** Raters and the judge see the same reference for each painting (`data/factsheets.json`). It is built from Wikipedia and Wikidata for the Wikipedia tier and from the ICCD records (translated into English by phi-4) for the gallery tier, and no model writes the key facts (`build_factsheets.py`, `derive_key_facts.py`, `translate_factsheets.py`).

**Rating.** Each description is scored 0/1/2 on subject, figures, placement and evidence by what it claims (2 specifically correct, 1 right category only, 0 contradicted by the reference). The primary metric is Σ = subject + figures + placement (0-6). The rater then picks the best description. Systems appear as A/B/C in an order that depends on rater and painting (`build_rating_app.py` generates the rating page). There were four raters, identified by pseudonyms: two lay raters (L1, L2), one art historian (E1) and a lay rater excluded because they never used the score 0 (L3).

**Results.**

| file | content |
|---|---|
| `data/submissions.txt` | the raters' transcripts as submitted (pseudonymised) |
| `results/human_ratings.json` | decoded ratings: per system, per rater, and one row per (rater, painting, system) |
| `results/agreement.json` | Krippendorff's alpha, Spearman correlations, forced-choice agreement, phi-4 vs. humans |
| `results/judge_rubric.json` | phi-4 scores on the same rubric (each painting in both presentation orders) |
| `results/{base,artseek_multiquery,gpt}[_normalized].json` | the answers (raw and as shown to the raters) and, for ArtSeek, the retrieval queries and retrieved ids |

To recompute them:

```bash
python rebuttal_experiments/human_eval/collect_ratings.py
python rebuttal_experiments/human_eval/agreement.py
```

To regenerate the answers, judge them and rebuild the rating page:

```bash
sbatch rebuttal_experiments/slurm/python.sh rebuttal_experiments/human_eval/run_local_models.py --system base
sbatch rebuttal_experiments/slurm/python.sh rebuttal_experiments/human_eval/run_local_models.py --system artseek_multiquery
OPENAI_API_KEY=... python rebuttal_experiments/human_eval/run_gpt.py
python rebuttal_experiments/human_eval/normalize_answers.py
sbatch rebuttal_experiments/slurm/python.sh rebuttal_experiments/human_eval/judge_rubric.py --systems base,artseek_multiquery,gpt
python rebuttal_experiments/human_eval/build_rating_app.py
```
